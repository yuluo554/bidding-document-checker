
设计要点：

1. **比对问题归约为结构化对齐**：两侧文档都解析成参数卡，符合性校核 = 参数卡字段级对齐 + 确定性规则判定；
2. **数值结论永远来自确定性规则**（FR-33），LLM 只做非结构化槽位兜底、复核建议与报告行文，不能改变 status；
3. **LLM 通路可整体关停**：规则通路独立完整，基准零 API 依赖。

## 二、技术栈

| 层 | 选型 | 理由 | 备选（不采用原因） |
|---|---|---|---|
| 语言 | Python ≥ 3.8（本机 3.8.8） | 语法底线=3.8：无 `match`、无 `X | Y` 类型联合、用 `Optional[]`/`List[]`；dataclasses 可用 | 3.9+ 特性会砍掉本机可跑性 |
| 解析 | stdlib `re` + 槽位函数 + 合法性校验 | 零依赖、可回归、确定性 | spaCy/NLTK（重依赖、对中文体例增益小） |
| 中间表示 | dataclasses + `to_dict/from_dict`（JSON 落盘） | schema 即代码，测试可断言 | pydantic（引依赖，v1 不必要） |
| 条文检索 | 纯 Python 余弦（TF 字频向量） | 条文规模小（数百块），免 faiss/annoy | faiss（重量级，规模不匹配） |
| 规则引擎 | JSON 规则表 + 按 `rule_type` 分派 handler | 规则可审阅、结论可挂依据 | 硬编码规则（不可审阅） |
| LLM 客户端 | httpx（`llm` extra）→ OpenAI 兼容 `/chat/completions` | 一套客户端适配主流供应商（含 qwen 兼容模式）；`enable_thinking=false` 提速 | openai SDK（额外依赖面大） |
| Web | FastAPI + uvicorn（`web` extra）+ 零依赖内联单页（vanilla JS + inline CSS） | 免构建、0 外链、断网可演示；Swagger UI 引 CDN → `/docs`、`/redoc` 显式关闭 | Vue3 vendor（前端复杂度不需要框架） |
| 报告 | python-docx（`report` extra） | docx 生成成熟、纯 Python | docxtpl（模板管理复杂度不值） |
| 围标图谱 | 自绘 SVG（无外部 JS 库） | 0 外链硬约束 | ECharts（CDN/内嵌体积大） |
| 测试 | pytest（`dev` extra） | 事实标准 | unittest（断言与夹具繁琐） |
| CI | GitHub Actions：ubuntu/windows × 3.8/3.12 四矩阵 | 环境差异早暴露（EOL/编码/版本） | 单矩阵（掩盖 Windows 坑） |

## 三、依赖分层（extras 纪律）

```toml
dependencies = []                       # core：解析/参数卡/引擎/知识库/基准 全部零依赖
[project.optional-dependencies]
web    = ["fastapi", "uvicorn", "python-multipart"]   # UploadFile 需要 python-multipart
report = ["python-docx"]
llm    = ["httpx"]
dev    = ["pytest"]                     # 测试期 import 也要被 extras 覆盖（TestClient→httpx）
```

**纪律**（姊妹项目实录教训）：extras 必须覆盖**运行期与测试期**真实 import——FastAPI `File(...)` 需要
python-multipart（漏了 uvicorn 启动即崩）、fastapi TestClient 需要 httpx（漏了 pytest 静默少跑不是报错）。
修复任何 extras 缺失后必须加"静态解析 pyproject extras 断言包名"的守门测试。

## 四、LLM 接入策略（可关停）

- 配置全部走环境变量：`BIDCHECKER_LLM_BASE_URL` / `BIDCHECKER_LLM_API_KEY` / `BIDCHECKER_LLM_MODEL`；
  未配置 → LLM 功能整体禁用，规则通路照常（CLI 提示而非报错）；
- 客户端必配：`enable_thinking=false`（qwen3 系）、`max_tokens` 截断后的 JSON 修复、超时+有限重试、失败降级规则通路；
- 防幻觉三件套：候选行压缩（只送含数字/关键词的行控制成本）、要求"原文编号+逐字摘录"（摘录不是原文子串即丢弃）、数值合法性范围校验；
- 默认供应商倾向 qwen 系列（DashScope 兼容模式），但**接口按 OpenAI 兼容设计，不锁定供应商**（详见 06 D8）。

## 六、工程与环境约束（本机实测前提）

1. **Windows + Git Bash + Python 3.8**：用 `py` 不是 `python`；脚本一律 `py -X utf8`；全程
   `PYTHONDONTWRITEBYTECODE=1`（含 pip install，防 pyc 损坏类随机崩溃）；
2. **EOL 门（M0 即预防）**：`.gitattributes` 设 `* text=auto eol=lf`；M1 起字节冻结 fixtures 配
   "出现 CR 即大声失败"守门测试——防 Windows `core.autocrlf=true` 导致全新 clone 基准全挂；
3. **编码**：源码/数据 UTF-8；控制台输出经 `py -X utf8`；Web 冒烟用 Python urllib 发请求，不用
   curl 命令行传中文（GBK 污染请求体）；
4. **测试分批**：测试多时分批跑（每批 ≤50），以退出码+汇总行+git status 硬验证；
5. **解析器已知陷阱清单**（M2 必防）：字符逐个定位的伪空格、多行标注按 y/x 邻近聚类合并、
   合并行内多构件按标签切分段、CRLF 残留、中文路径、GBK 控制台编码。
